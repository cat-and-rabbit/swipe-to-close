# 1.1.0 検証記録

検証日: 2026-09-12

## 実装の変更

- 閉じるための履歴挿入とページのsessionStorage使用を廃止。
- 新規タブの起点をNavigation APIの履歴キーで識別し、拡張機能側でタブ別に保存。
- 通常の移動、リロード、SPA、サイト間の戻り、履歴の置換を区別。
- タブごとの非同期処理を順序付けし、全タブ共通の配列上書きによる競合を解消。
- 戻る方向の横入力を直接検出。減速時に判定し、慣性の最後まで待つ遅延を短縮。
- 起点ではネイティブ戻るの開始を抑止。通常の履歴位置と横スクロール領域には介入しない。
- ドキュメントの再確認、可視状態の確認、ウィンドウごとのガードとジェスチャー開始時刻で連続クローズを防止。

## 自動検証

環境: macOS / 通常版 Google Chrome 152.0.7977.84 / Node.js 22.22.3 / Playwright 1.62.1。

- `npm test`: ジェスチャーと状態管理のロジックテスト。19項目すべて成功。
- `npm run test:browser`: 独立した一時プロファイルへ未パッケージ拡張を読み込む統合テスト。
- 配布ZIPを新しいフォルダへ展開し、`EXTENSION_PATH` を指定して同じブラウザテストを実行。22項目すべて成功。
- Service WorkerはDevTools Protocolで実際に停止し、`running → stopping → stopped → starting → running` を観測してからクローズ成功を確認。
- 状態の観測には `Runtime.evaluate` の `userGesture: false` を使い、クリック前のテストを観測操作で変化させない。

主なブラウザ検証項目:

1. 未クリックの新規タブのクローズ、履歴件数・history.state・sessionStorageの保持。
2. 空タブからの起点ではwheelの既定動作を抑止し、起点以外では抑止しない。
3. target="_blank"、⌘クリック、中クリック、window.open、rel="opener"。
4. 縦スクロール、横スクロール領域、逆方向へのキャンセル、ピンチ相当の修飾キー入力、iframe除外。
5. 異なるサイト・同じサイト・SPA・ハッシュの履歴を戻り、起点でだけ閉じる。
6. リロード、HTTPリダイレクト、明示的な置換、読み込み直後のJavaScriptリダイレクト。
7. 16タブ同時作成と削除で、全対象レコードの保持と削除を確認。
8. 続く慣性入力で、切替先のタブを閉じない。
9. Worker停止後の再起動でも起点を保持。

ブラウザテストのwheel入力はDevTools経由の入力であり、物理トラックパッドの手動検証とは区別する。ナビゲーションの回帰テストにはhistory.back()も使用するが、それだけを実スワイプの成功根拠にはしない。

## 実機スワイプ

- ユーザーが通常版Chromeの検証ウィンドウで、クリックせずにスワイプして閉じることを確認。「閉じましたが、タイムラグがかなりあります」とのフィードバックを受けた。
- 最初の試作は入力の完全な停止を待っていた。物理入力のログでは慣性が1〜3秒程度続く例があった。
- 減速で判定する版では、未クリックのページから3回のクローズを記録。入力開始からタブのcloseイベントまでは342ms、240ms、311msだった。この少数の手動サンプルは、すべての機器での応答時間を保証するものではない。
- 最後に追加した起点でのネイティブ戻る抑止を含む最終版について、ユーザーから「実際の動作確認ができました。良さそうです」との確認を受け、手動の受け入れ確認を完了した。

## 残る範囲・制限

Chrome 106は採用APIに基づく下限であり、そのバージョンでの実機確認はしていない。別のトラックパッド、異なるmacOSジェスチャー設定、サイト独自の特殊な入力処理については未検証。

クロスオリジンiframeなど埋め込みフレーム上のジェスチャー、スクリプトを注入できないページ、起点を確定できない復元タブは対象外。wheelだけで指の本数やネイティブスワイプの終了を完全に識別することはできず、クローズ成立後の逆方向操作では取り消せない。
